# writing-pipeline — 주제에서 게시 직전 원고까지

## 원칙 — 어기게 되면 멈춘다
- raw/는 읽기만 한다. 결과는 모두 `out/YYYY-MM-DD_슬러그/` 안에만 쓴다.
- 게시 · 업로드 · 메일 발송 · 외부 전송을 하지 않는다. 8단계의 끝은 언제나 [게시 승인] 멈춤이다.
- 근거는 원문을 직접 열어(WebFetch로 내용을 읽어) 확인한 출처만 쓴다. 검색 결과의 요약 문구만 보고 쓰지 않는다.
- 모르는 것은 지어내지 않고 〔확인 필요〕로 남긴다. 사람이 정할 것을 대신 정했으면 〔제안〕으로 표시한다.
- 단계 파일을 다 쓴 뒤에 진행상태.md를 고친다. 진행상태.md를 고치기 전에는 다음 단계로 가지 않는다.
- 단계를 건너뛰지 않는다. 멈춘 뒤 뒤쪽 단계를 먼저 하지 않는다.

## 0. 시작 — 새로 할지 이어 갈지
1. 인자가 `raw/주제카드_*.md`이면: 그 주제 카드를 가리키는 `out/*/진행상태.md`가 이미 있는지 먼저 찾는다. 있으면 새 폴더를 만들지 않고 그 폴더로 이어 간다.
2. 인자가 out/의 폴더이거나 "이어서"이면: 그 폴더(지정이 없으면 상태가 '완료'가 아닌 가장 최근 폴더)의 진행상태.md를 읽는다.
3. 인자가 없으면: 상태가 '완료'가 아닌 진행상태.md 목록을 보여 주고 어느 것인지 묻는다. 없으면 raw/의 주제 카드 목록을 보여 주고 묻는다.
4. 이어 갈 때는 일을 시작하기 전에 한 줄로 먼저 말한다 — "〈주제〉: 단계 N까지 끝, 단계 M에서 [멈춤 종류]로 멈춤 — 다시 시작 조건을 확인함".
5. 멈춤이었다면 진행상태.md의 '다시 시작 조건'이 채워졌는지 확인한다. 안 채워졌으면 같은 멈춤을 다시 보고하고 끝낸다. 끝난 단계를 다시 하지 않는다.
6. 새로 시작하면 `out/YYYY-MM-DD_슬러그/`를 만들고 `references/진행상태_양식.md` 그대로 진행상태.md를 만든다. 슬러그는 주제의 핵심어 2~4개를 `-`로 잇는다.

## 단계 1 기획 → 01_기획.md
- 주제 카드를 읽는다. 필수 칸(주제 · 매체 · 분량) 중 하나라도 비면 [자료 부족] 멈춤.
- 적을 것: 독자 · 핵심 메시지(카드에 없으면 〔제안〕을 적되 01_기획.md 맨 아래 `## 사람 결정`에 사람이 확정하기 전에는 [자료 부족] 멈춤) · 이 글이 답할 질문 1개 · 각도 · 제목 후보 3개 · 소제목 목차와 소제목별 분량 · 핵심 주장 목록.
- 핵심 주장에는 C1, C2… 번호를 붙이고 [사실] / [의견]을 표시한다. [사실]마다 "무엇을 어디서 확인해야 하는지"를 한 줄로 적는다.

## 단계 2 검색 관심도(간접 판단) → 02_관심도.md
- 웹 검색으로 간접 지표를 모은다. 쓴 검색어(3개 이상)와 검색한 날을 함께 적는다.
  - ① 최근 6개월 안의 관련 기사 · 글 — 날짜를 페이지에서 직접 확인한 것만 센다. 대표 5건까지 표로(날짜 · 매체 · 제목 · 주소). 날짜를 확인하지 못한 것은 〔날짜 확인 필요〕로 따로 적고 세지 않는다.
  - ② 사람들이 묻는 질문 — 질문형 제목 · 자주 묻는 질문 · 커뮤니티의 질문 제목
  - ③ 연관 검색어 — 검색 결과에 함께 나온 말
- 판정은 숫자로 한다 — N: 6개월 안 날짜 확인 건수 · M: 그중 최근 3개월 안 건수 · Q: 질문 수
  - 높음: N ≥ 5이고 M ≥ 2
  - 보통: N이 2~4, 또는 N ≥ 5인데 M < 2
  - 낮음: N ≤ 1
- 판정 · N · M · Q · 근거 한 줄을 적고, 최근 3개월의 글이 다루는 쪽(화제가 옮겨 가는 방향)을 한 줄로 적어 01의 각도와 맞는지 표시한다.
- '낮음'이면 각도를 바꿀 후보 2개를 적고 [사람 판단] 멈춤. 웹 검색을 쓸 수 없으면 [자료 부족] 멈춤. 그 밖에는 멈추지 않고 단계 3으로 간다.

## 단계 3 원문 조사 → 03_원문.md
- 01의 [사실] 주장마다 1차 원문을 찾아 직접 연다. 연 원문마다 적을 것: 주소 · 원문 제목 · 발행 주체 · 발행일 · 열람일 · 확인 위치(조 · 항 · 쪽 · 문단) · 발췌(원문 그대로 두 문장 이내).
- 법령은 국가법령정보센터 원문, 정부 정책은 부처의 보도자료 · 고시 원문, 해외 규제는 공식 관보나 기관 페이지, 논문은 원문(초록만 보았으면 그렇게 적음).
- 기사 속 재인용만 보고 적지 않는다. 열지 못한 원문은 "열람 실패 — 이유"로 적는다.
- 주장 하나를 끝낼 때마다 파일에 덧붙이고 진행 메모에 "단계 3 — C2까지"처럼 적는다.
- 원문을 못 연 [사실] 주장이 남으면: 스스로 빼지 않는다. `## 뺀 주장`에 후보로 적고(그 주장 없이 01의 질문에 답할 수 있는지 의견 한 줄) [자료 부족] 멈춤 — 03_원문.md 맨 아래 `## 사람 결정`에 그 C번호의 '빼기'가 적힌 뒤에만 단계 4로 간다.

## 단계 4 출처 신뢰 → 04_출처.md
- `references/출처등급.md` 기준으로 출처 표를 만든다: [n] · 출처 · 발행 주체 · 발행일 · 열람일 · 등급(A/B/C) · 최신성 · 뒷받침하는 주장(C번호).
- 주장별 충족 표: [사실] 주장마다 A 1개 이상 또는 서로 독립된 B 2개 이상이면 충족.
- 미충족이 있으면 출처를 더 찾는다(주장마다 최대 두 번 더 검색). 그래도 미충족이 남으면 [자료 부족] 멈춤 — 그 주장을 뺄지는 사람이 정한다.

## 단계 5 집필 → 05_초고.md
- `raw/문체샘플/`에서 이름이 `_`로 시작하지 않는 .md · .txt 파일을 센다. 2편 미만이면 [자료 부족] 멈춤.
- `raw/편집기준.md`가 없으면 [자료 부족] 멈춤.
- 쓰기 전에 05_초고.md 맨 위에 '문체 메모'를 적는다: 종결 어미 · 문장 길이 · 단락 길이 · 인칭 · 연결 방식 · 쓰지 않는 표현 — 근거로 샘플 문장을 하나씩 짚는다(샘플 문장을 본문에 옮겨 쓰지 않음).
- 01의 목차와 분량을 따른다. 사실 · 수치 · 인용 문장 끝에 [n](04의 번호)을 붙인다. 04에서 충족되지 않은 주장은 쓰지 않는다.
- 직접 인용은 원문 그대로 · 따옴표 · 두 문장 이내. 남의 글의 구성이나 문장을 바꿔 옮기지 않는다.
- 끝에 참고문헌(본문에 쓴 번호만)과 본문 글자 수(공백 포함)를 적는다.

## 단계 6 이미지 → 06_이미지/
- 도표: 04에서 충족된 수치나 사실만으로 SVG를 직접 쓴다 — 글자는 `<text>`, 글꼴은 sans-serif, 아래에 '출처: [n]'. 수치가 없으면 개념도(단계 · 관계)만 그린다.
- 썸네일: 제목과 핵심어만으로 단순한 SVG 1개 — 사진 · 로고 · 실존 인물 · 남의 캐릭터를 넣지 않는다.
- 사진형 이미지는 `이미지_프롬프트.md`에 외부 생성기용 프롬프트만 적는다 — 실존 인물 · 상표 · 특정 작가의 화풍을 요청하지 않고, 쓸 때 붙일 'AI 생성 이미지' 표시 문구를 함께 적는다.
- `이미지_목록.md`: 파일마다 제작 방식(직접 그린 SVG / 생성 프롬프트) · 쓰인 출처 번호 · 대체 텍스트.

## 단계 7 검수 → 07_검수.md
- `manuscript-reviewer` 서브에이전트에게 맡긴다. 넘길 것은 원고 폴더 경로 · `raw/편집기준.md` · `raw/문체샘플/` 경로뿐 — 만든 과정은 넘기지 않는다.
- 돌려받은 지적을 07_검수.md에 회차를 붙여 그대로 옮긴다.
- [필수] 지적이 있으면 05(필요하면 06)를 고치고, 고친 곳을 07에 적은 뒤 다시 맡긴다. 2회차에도 [필수]가 남으면 [사람 판단] 멈춤.
- 서브에이전트를 쓸 수 없으면 스스로 검수하지 말고 [사람 판단] 멈춤("검수자 없음").

## 단계 8 저장 → 08_최종.md
- 05를 최종본으로 옮긴다(문체 메모는 뺌). 맨 위 첫 줄: `상태: 게시 승인 대기 — 게시하지 않음`.
- 아래에 '게시 승인 요청'을 붙인다: 〔제안〕으로 남은 결정 · 〔확인 필요〕 목록 · 뺀 주장 · 검수 결과 요약 · 이미지 목록 · AI를 써서 만들었다는 사실을 밝힐지(사람 판단).
- 진행상태.md를 [게시 승인] 멈춤으로 바꾸고 끝낸다. 사람이 진행상태.md의 '게시 승인' 칸에 날짜와 결정을 적으면 다음 호출 때 상태를 '완료'로 바꾼다. 게시는 사람이 한다.

## 멈출 때 — 모든 멈춤에 공통
1. 진행상태.md를 고친다: 상태 `멈춤 — [자료 부족]` / `멈춤 — [사람 판단]` / `멈춤 — [게시 승인]` · 멈춘 이유 · 사람이 할 일(어느 파일의 어느 칸에 무엇을) · 다시 시작 조건 · 다시 시작 문장.
2. 진행 메모에 한 줄을 덧붙인다(날짜와 시각 · 단계 · 멈춤 종류).
3. 사용자에게 세 줄로 보고하고 끝낸다 — 어디서 멈췄나 / 왜 / 무엇을 해 주면 이어 가나.
